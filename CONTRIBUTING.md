# Contributing / 参与开发

Thank you for helping improve CoLayout. Human contributors and coding assistants use the same architecture, tests and review requirements.

请先阅读 [架构](docs/zh/architecture.md) 与 [开发流程](docs/zh/development.md)。欢迎人工开发者与编码助手参与，适用相同的验证与评审规则。

- Explain the concrete problem and resulting behavior. Keep shared rules in domain services.
- Use synthetic reproductions. Never submit PDK files, credentials, proprietary layouts, private reports or conversation logs.
- Preserve native transactions, unknown-result recovery, scoped ownership and shared UI/API semantics.
- Include relevant test results and limits. Native integration results must state their actual scope.
- Keep Chinese/English onboarding and usage docs aligned when user behavior changes.
- Contributions are provided under the repository's MIT license; retain notices for any third-party code and identify its source/license. Do not copy code whose redistribution terms are unknown.
- Open an issue for substantial behavioral/design changes before a large rewrite. Small fixes can be proposed directly.

A useful issue states the APP/tool versions, minimal steps, expected/actual behavior and a sanitized error code. Review screenshots and metadata before attaching them.

A useful pull request leads with the user-visible problem, summarizes the final implementation, and explains testing plus known limitations. Do not include abandoned conversation history.
