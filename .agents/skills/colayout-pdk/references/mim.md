# MIM 层位与独立过孔防护

MIM 电容可能让某类普通标准孔的实际电气落点变为上极板。公开金属 PIN 正确，不代表在其整个矩形内从任意方向打孔都能到达该极板。配置是局部防护，不能冒称完整器件提取。

## 从哪里找

1. 用户样例中的原生 MIM 实例：查看实例/master、公开 PIN 的 LPP、原生图形、上下金属及接触孔。collect 保存 `sample-layout.json`、`native-technology.json` 和 `device-evidence.json`；不可按 cell 名含 mim 就认定。
2. 技术文件及标准 via 定义：核对实际金属栈顺序、层名/用途及候选孔连接的两层。不要仅看屏幕颜色或用 GDS 数字层号填 OA 层名。
3. 当前 PDK/选项对应的 LVS/提取规则：核对实际启用宏，再查 MIM 器件的 PLUS/MINUS 定义、孔与 MIM 的交/差派生层，以及 CONNECT 语句。实际 MIM mask 可能与 dummy、检查或识别标识层不同，不能选错覆盖层。必要时查工艺说明，不需要为了配置重跑完整 DRC/LVS。
4. 用实际 stream map 将规则中的 GDS 层映射回 OA 图层/用途。记录文件、选项、定义或用户确认作为 source。不能把当前工艺的层位复制到另一个 PDK。

## 配置形状

```json
{
  "drc": {
    "mim_capacitor": {
      "status": "configured",
      "lpp": ["实际MIM覆盖层", "实际用途"],
      "lower_metal": "实际下方金属",
      "upper_metal": "实际上方金属",
      "source": "实际资料位置、启用选项与接触定义；或用户明确确认"
    }
  }
}
```

这里只展示包内字段，提交时保留其他统一配置。软件会校验 LPP、金属角色、标准孔层对及已有金属栈顺序；不会替 Agent 猜测它们。

没有足够证据时使用 `status: unconfigured`，已核实的部分字段可保留。check/submit 可以保留待确认状态，UI 审核启用前必须由人填写确认。工艺确实没有 MIM 时使用 `status: unsupported`，层位留空。旧文件缺字段按未配置读取，不自动认成不支持，也不偷偷套用其他 PDK。

## 检查边界

本地 DRC 检查当前层独立标准过孔，包括导入的独立孔和组合过孔的各级；按切孔真实几何与配置的 MIM LPP 面积重叠判断，报 `MIM_VIA_BLOCKED` 工艺错误。原生 PCell 内自带的孔不检查，原生层次/子操作区仍按既有黑盒规则处理。只有金属包围框重叠或边界相接不会触发。本地错误不受服务器报告过滤影响。

它不改绘图权限、普通连通性或人用高亮。失败后通常应把孔移到 MIM 区外，或选工艺允许的下层接入方式；不能自行修改配置关闭检查来完成版图。
